# The GoatConf site

Plain HTML and CSS for goatconf.com, the conference's own home (ADR
`wiki/org/adrs/goatconf-ba-and-google-forms.md`). There is no build step for
the hand-written pages; two pages are generated from records. Open
`index.html` through any static server to preview it; the budget page reads
`ledger.csv`, which a browser only allows over http.

## Pages

- `index.html`: the home page, a sticker album (`DESIGN.md`).
- `program.html`: generated by `tools/program.py build` from
  `program/*.md` (accepted sessions) and `extensions/*.md` (Saturday and
  the days around the talks). Edit the records, not the page.
- `extensions.html`: generated by `tools/extensions.py build` from
  `extensions/*.md`.
- `speakers.html`, `supporters.html`: generated by `tools/speakers.py build`
  from `speakers/*.md` and `supporters/*.md` (consented speaker profiles,
  and the companies that fund speakers' travel). Photos and logos live in
  `img/speakers/` and `img/supporters/`.
- `talk.html`, `add.html`, `register.html`, `contact.html`: what each form
  asks and what happens next, each with a button to its Google Form.
- `travel.html`, `charter.html`, `code-of-conduct.html`, `budget.html` with
  `ledger.csv` (one line per payment or gift; columns: date, item, kind,
  covered_by, supplier, amount_eur, in_kind, receipt_in_hand, note).
- `goatconf.css`, `album.js` (stickers peel and settle as they come into
  view), `ledger.js`, `favicon.svg`, `fonts/` (self-hosted, SIL Open Font
  License, see `fonts/LICENSE.md`).

## Navigation and the home page

Every page carries the same top bar, written by `tools/nav.py apply` (the
generators add it to their own pages). The home page is hand-written except
three parts that `tools/home.py build` fills from the records: the days
(from `DAY_PLAN` in `tools/program.py`), the speakers and the supporters;
it also renumbers the album's stickers in order. The local CI checks both.

## Places to eat and stay

`tools/places.py build` draws the two maps on the travel page from
`places/places.yml` and an OpenStreetMap extract in `sources/web/osm/`
(the "© OpenStreetMap contributors" line under each map is required by its
licence). Only places with `approved: true` appear; the organiser approves
each one. `--all` previews every place without changing what is approved.

## For search engines and AI agents

`tools/agents.py build` writes the files agents and crawlers read, from
the same records as the pages: `llms.txt` (a plain-text guide to GoatConf
and every page), `program.json` (days, rooms, sessions and events),
`goatconf-2027.ics` (the three days for a calendar, linked from the
program page), `sitemap.xml`, `robots.txt`, and the schema.org event data
in the head of `index.html`. Run it after any program, speaker or event
change; the local CI fails if they are stale.

## Brand and shareables

`brand/` holds the seal, the small form, the goat and the lockups, built by
`tools/brand.py` (SVGs checked by the local CI; `render` also writes the PNG
and print PDF files). `share/` holds the banners, the Luma cover, the
link-preview image and the posts, rendered by `tools/shareables.py render`
from the same seal; it also makes an "I'm speaking" card per speaker and a
"thank you" card per supporter. Every page carries link-preview tags from
`tools/meta.py`; the generated pages add them themselves.

## The forms

Every link to a form is an anchor with `data-form="talk|add|register|contact"`.
The URLs live in `files/forms.yml`; `tools/formlinks.py links` writes them into
the pages and `tools/formlinks.py check` (run by the local CI) checks them.
Registration is the Luma event: its link also carries Luma's checkout
attributes, and `register.html` loads Luma's checkout script, so the button
opens registration over the page. The other three are Google Forms in the
organiser's GoatConf folder in Drive; `tools/google-forms/README.md` lists
what each asks and how it is set up.

## Publishing

goatconf.com is served by GitHub Pages from the public repository
misabegovic/goatconf. One GitHub Actions workflow,
`.github/workflows/publish-site.yml` (generated by `tools/pages.py`),
uploads this folder unchanged and deploys it on every push to `main` that
changes `files/site/`; it builds and checks nothing. Every merge to `main`
therefore publishes, so run `bash tools/ci-local.sh` before merging: it
fails while a generated page is stale, a form link is empty, or the
workflow has changed. The decision is in
`wiki/org/adrs/goatconf-ba-and-google-forms.md`.

One-time setup:

1. **Pages.** In the repository's Settings, Pages: source "GitHub
   Actions"; custom domain `goatconf.com`; enforce HTTPS once the
   certificate is issued.
2. **DNS at Namecheap.** Domain List, goatconf.com, Manage, Advanced DNS.
   Remove the parking records, then add four A records for host `@`,
   185.199.108.153, 185.199.109.153, 185.199.110.153 and 185.199.111.153,
   and a CNAME record for host `www` to `misabegovic.github.io.`
   (`sources/web/tooling/github-pages-custom-domain-2026-10-12.md`).

## Photos

The site shows no photo credits, on the organiser's decision of
2026-10-12 (`sources/conversations/2026-10-12--org--no-photo-credits.md`).
Provenance and licences stay recorded in `assets/images/` and
`sources/web/images/`. Prices on the
home page were checked on 2026-10-07 (`wiki/org/tuzla.md`); update the date
with the numbers.
