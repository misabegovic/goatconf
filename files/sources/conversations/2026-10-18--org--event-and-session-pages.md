After the meetup's phone fixes, the organiser wrote, verbatim:

> Also, I can't click on the thing on the program. I want to open it and see details. We need the same for every session too in the future
> We should also rework https://goatconf.com/extensions.html and have them link to the site of that particular event
> Awesome. We should also accept more than one meetup and make it clear more than one thing is acceptable

The agent asked four questions, and the organiser chose:

- **Where an event opens:** "Its own page". Each accepted event gets a
  page on goatconf.com, like speakers do, named after its record
  (goatconf.com/event-bh-professionals-meetup): when, where, cost, how
  to join, host, who pays, the contact and the host's description.
- **"The site of that particular event":** "Our page, linking out". The
  events page becomes an index of cards, each opening the event's own
  page, which links to the host's registration ("Register with the
  host") and contact.
- **Sessions:** "Now, same pattern". Every session on the program gets
  its own page, named after its title
  (goatconf.com/session-<title>), and its sticker opens it; speaker
  names on the sticker stay links to their pages, and a speaker's page
  links the session's page. No session exists yet, so it is tested with
  a sample record and goes live with the first one.
- **More than one of a kind on the home page:** "Kinds stay open, events
  above". All eight kinds keep their "Yours?" stickers; every accepted
  event, any kind, shows in an "Accepted so far" row above them, with
  the line "More than one of each is welcome: a second meetup, another
  hike, a dinner every night." The same line is on the events page and
  the propose an event page.

In the same message thread the organiser answered "Yes" to merging PR
#81, which was merged before this work began.
