## https://paulca.com/blog/carlos/ ("CARLOS", October 27, 2026)

> Also in the meantime, computers got very, very fast. [...] Computers were already fast. I don't think people realise how fast computers are.
>
> Why? Because software still feels slow!

> The reason for all of this is enshittification. All of the things that contribute to web app slowness are for things that are optimised not for the user, but for the corporation providing the service.

> CARLOS stands for:
> Cost-effective
> Available
> Replicated
> Lightweight
> Open
> Secure

> I've spent the last few months building apps like this and convincing myself that it's no longer a given that we need to hire big tech to get world class uncompromising software.

> My question to myself last December was: can GenAI tools do the work I was doing?
>
> My question six months later in July was: can GenAI tools build things that I never could, and big tech never would?

> It's extracted from 19 apps that are in some state of production at the time of writing.

## https://paulca.com/blog/deshittification/ ("Deshittification", October 29, 2026)

> I've come to realise over the last few days that CARLOS, the nebulous project that I have uncovered and appear to be stewarding into the world, is my effort to participate in the janitorial pursuit of deshittification.

> I think the role of the software engineer or product manager or software vendor in late 2026 is deshittification. Let's make deshittification a competitive advantage. Let's make speed a required default.

## https://carlosframework.com/

> A software design approach for building and shipping uncompromising apps in the agentic age
> Ship 12x faster for 10x less. Simplify your stack. Build better software.

> Rastrillo
> A full-stack Go web framework. Everything you need to build CARLOS apps today.

> By combining GenAI, old school computer science principles, and embracing modern tech, CARLOS rejects both monoliths and microservices, in favour of many small full-stack instances.

> 10× lower running costs from reducing AWS resources
> 87% less JavaScript by rendering pages on the server
> 12× faster to ship by building with agents on CARLOS principles
> 4.5× faster first render
> 5× faster responses

> Numbers based on real data from Tito. The agents insisted on measuring everything.
